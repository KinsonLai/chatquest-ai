# ChatQuest AI 0.4.0

`prepare_turn` can now include predeclared `checks` and a known `world_preview`. A scene that previously needed prepare, roll, preview and commit can use prepare and commit. If a result determines the next check or elapsed time, keep the separate calls.

This uses the existing dice and event algorithms in the preparation transaction. Bundled checks require the last confirmed `expected_revision`; stale versions reject before rolling. Failed batches roll back, exact repeats preserve recorded dice, and commit still validates the full check set. No save-schema or operating-policy-byte change.

The server instructions and workflows explain how to reuse full canon text, recorded character knowledge and an already-read policy without fetching them again. Context loss still requires a fresh read.

Validation: 29 tests pass, including failed dice, replay, transaction rollback, stale revisions, a completed MCP story and a played IF that preserves the original branch. A 30-turn localhost HTTP benchmark used 60 rather than 120 tool calls; its median protocol time was 30.71 rather than 61.60 ms, with identical final GM state. This excludes LLM generation and internet latency; it does not promise that ChatGPT replies will be twice as fast. See [the measurements](https://github.com/KinsonLai/chatquest-ai/blob/v0.4.0/docs/performance.md).

```sh
npx --yes --package=https://github.com/KinsonLai/chatquest-ai/releases/download/v0.4.0/chatquest-ai-0.4.0.tgz chatquest
```

Keep the same database path, restart the upgraded MCP server and refresh the chat client's tool metadata. Old clients can continue using the separate tools.
